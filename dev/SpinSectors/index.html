RPAToolkit.SpinSectors

RPAToolkit.SpinSectors.SPIN_SYMMETRIES — Constant
SPIN_SYMMETRIES

The spin symmetries a model can have, from most to least symmetric: "SU2" (no spin-orbit coupling, H = h ⊗ 1), "U1z" ($S_z$ conserved: no spin-flip hopping, but up and down differ, as with Ising spin-orbit coupling) and "none". The bare stage stores the 0-based index of the one it used as spin_symmetry in each .npz.

source
RPAToolkit.SpinSectors.VERTEX_SLOTS — Constant
VERTEX_SLOTS

The channel layout of every interaction matrix: slot N holds minus the charge vertex, $-U^{(c)}$, and slots X, Y and Z each hold the spin vertex $U^{(s)}$. These are the physical channels, so the layout is valid with spin-orbit coupling, when $\chi$ mixes them. Interaction files and run_rpa output record this string under "vertex_slots", and run_rpa refuses an interaction file without it: before 2026-11-01 slot N held $U^{(s)}$ and slot Z held $-U^{(c)}$, which is only equivalent without spin-orbit coupling.

RPAToolkit.SpinSectors.channel_pairs — Method
channel_pairs(symmetry) -> Vector{Tuple{Int, Int}}

The channel pairs (a, b) (directions, 0 = N to 3 = Z) for which $\chi^{ab}$ can be nonzero under symmetry: the four diagonal ones for "SU2"; NN, NZ, ZN, ZZ and XX, XY, YX, YY for "U1z", where $S_z$ conservation only connects operators of equal $S_z$ charge; all sixteen for "none".

RPAToolkit.SpinSectors.off_sector_norm — Method
off_sector_norm(M, sectors) -> Float64

The largest |M[i, j]| with i and j in different sectors: zero exactly when M is block diagonal in them.

RPAToolkit.SpinSectors.spin_sectors — Method
spin_sectors(symmetry, d) -> Vector{Pair{String, Vector{Int}}}

The channel sectors a 4d × 4d matrix (channel innermost, entry (p, mu) at 4 (p - 1) + mu) is block diagonal in when the model has symmetry, as name => indices:

  • "SU2": "charge" (N), "spin z", "spin x", "spin y".
  • "U1z": "longitudinal" (N and Z, which $S_z$ conservation leaves coupled) and "transverse" (X and Y).
  • "none": "all".

RPAToolkit.SpinSectors.stored_spin_symmetry — Method
stored_spin_symmetry(data; model_symmetry) -> String

The spin symmetry a bare-stage .npz was contracted under, i.e. which channel pairs it holds.

Files written before 2026-11-01 do not record it. Those with bubble_spin_factorized = 1 are "SU2". The rest hold the diagonal pairs of a spinful bubble, which is the whole of $\chi$ only when the model is "SU2": accepted when model_symmetry says so, refused otherwise.
